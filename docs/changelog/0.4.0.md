# howlto v0.4.0

Date: 2026-08-04

本版本补全无配置文件启动, 新增输出偏好提示词, 重建工具协议并改善流式进度展示. 使用旧版本的用户无需迁移现有配置.

## Highlights

- 无需先创建配置文件, 提供 API key 或环境变量即可直接使用.
- 用 command/cmd/c 或 text/txt/t 开头, 可以明确要求命令候选或纯文本回答.
- 工具调用, 多轮失败恢复和流式进度输出更稳定, 外部命令增加超时保护.
- `--version` 自动显示构建来源, 精确 tag, 非 tag commit 和脏工作区可区分.
- Release 流程迁移到 docs/changelog, 手动构建也会生成校验产物.

## Upgrade Notes

1. 现有 config.toml 和 profiles.toml 会继续加载, 不需要手动迁移.
2. 需要持久化配置时, 可以运行 `howlto --init-config` 创建缺失文件.
3. 检查 `howlto --version` 是否显示 `v0.4.0` 或带 commit 的版本.

## Features

- 文件不存在时使用内置配置和默认 profile, 并支持 HOWLTO_* 与 OPENAI_* 环境变量覆盖.
- 新增 `--init-config`, 只创建缺失配置, 不覆盖已有文件.
- 提示词首词支持输出偏好, 命令候选和纯文本回答可分别指定.
- 命令候选带独立 description, 选择后仍可查看全部候选项.
- 默认 prompt 优先使用 rg, fd 等现代工具, 并提供可复现的文本回答命令.
- `--plain` 对命令候选只输出原始命令, 纯文本回答会移除 Markdown 标记.

## Bug Fixes

- 修复多步骤工具调用后空 final, 无效工具和临时 provider 错误导致的失败.
- 外部命令增加 20 秒超时, 避免 explore, man, tldr, thefuck 等阻塞 agent.
- man 输出并发读取 stdout 和 stderr, 避免大输出时管道死锁.
- 流式进度信息不再展示工具调用 JSON, 但原始内容保留在 agent 历史中.

## Performance

- 重建工具协议, 减少历史冗余并让多轮失败恢复更直接.
- 优化 scrolling 输出合并和 ANSI 清理, 大段流式文本更流畅.
